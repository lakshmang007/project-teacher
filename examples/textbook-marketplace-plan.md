# Where to start: a textbook marketplace for your college

**The idea:** a place where students at your college list old textbooks and other students find them.

**Version 1 (the smallest useful thing):**
- Sign up and log in, with sign-up limited to your college email.
- Post a listing with title, price, condition and contact info.
- Browse and search listings.
- Mark your own listing as sold.

**Left out for now:** payments, in-app chat, photos and ratings. Students can meet on campus and pay each other directly, which keeps the first version small.

**Later ideas:** photos, filter by course or semester, "wanted" posts, wishlists, and email alerts when a book you want is listed.

**Stretch question:** what would make this feel like yours? For example, a "books for my branch and semester" view.

## Expert brief
- **Start with:** plain HTML, CSS and JavaScript for the pages, plus Supabase (free) for login and saved listings. You don't write your own login system.
- **From day one:**
  - Turn on the database's access rules before anyone signs up.
  - Never put secret keys in public code.
  - Give every input a label.
- **Watch out for:**
  - Starting with a big framework.
  - Leaving the database open to anyone.

## Simplest path

| | A (recommended) | B |
|---|---|---|
| Setup | 3 files plus Supabase | Next.js project, many files, Node install |
| Good for | First version, learning | Large apps later |
| What you lose | Less structure if it grows big | Much more to learn first |

## Learn these 3 terms
**Term:** Database
**Meaning:** A saved table of information that stays after you close the page.
**Example:** A school register. Each listing is one row.

**Term:** Authentication
**Meaning:** Proving who you are, for example by logging in.
**Example:** Showing your ID card at the library gate.

**Term:** Row-level security
**Meaning:** Rules saying who can read or change each row.
**Example:** You can erase your own name from the register, but not anyone else's.

## Build checklist (paste each prompt into Claude Code)
1. **Setup.** *"Create a folder with index.html, style.css and app.js. Show a page titled 'Campus Books' with a heading. Don't add libraries."*
   **Done when:** you open index.html in a browser and see the heading.
2. **Fake listings.** *"In app.js, hold 3 sample textbooks in a list and show them on index.html. Change only app.js and index.html."*
   **Done when:** three books appear on the page.
3. **Post form.** *"Add a form to add a listing (title, price, condition, contact). Every input needs a label, the button needs a clear name, and it must work with the keyboard alone. Save to the in-page list only."*
   **Done when:** you add a book with Tab and Enter and it appears.
4. **Look and phone layout.** *"Style the page in style.css. Add the viewport meta tag. Make it readable on a phone."*
   **Done when:** nothing scrolls sideways in a phone-width window.
5. **Real database.** *"Connect Supabase. Create a listings table, and save and load listings from it. Keep keys out of public code. Tell me what I must click in Supabase."*
   **Done when:** a listing is still there after you refresh the page.
6. **Login.** *"Add Supabase email sign-up and login, restricted to my college email domain."*
   **Done when:** a college email can sign up and a Gmail address is rejected.
7. **Access rules.** *"Turn on row-level security: anyone logged in can read listings, but only the owner can edit or delete theirs."*
   **Done when:** a second account can't delete the first account's listing, even by typing the address directly.
8. **Search and sold.** *"Add a search box and a 'mark as sold' button for my own listings."*
   **Done when:** searching "physics" filters the list, and sold items disappear.
9. **Go live.** *"Walk me through putting this on Netlify, step by step."*
   **Done when:** a friend opens the link on their phone and signs up.

**After the build:** try one failing case, test with the keyboard alone, and ask a friend to use it without help.

### Reviewer's note

The plan is sound, with one ordering issue worth knowing: the expert brief says to turn on the database's access rules *before anyone signs up*, but the checklist adds sign-up in step 6 and the access rules in step 7. When following this plan, do steps 6 and 7 together, before sharing the sign-up page with anyone.
