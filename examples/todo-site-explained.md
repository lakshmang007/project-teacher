## What this project is

A small **to-do list website**. You type a task and click Add (or press Enter). You can tick tasks as done, delete them, and they're still there after you refresh the page.

**Files:**
- `index.html` has everything: the page structure (HTML), the look (CSS in `<style>`, lines 7–16), and the behavior (JavaScript in `<script>`, lines 26–84).
- `BUILD-CHECKLIST.md` is the 7-step plan used to build it. Steps 1–7 are ticked. Only the "After the build" items are left.

There is no server, no database and no library. You can open it by double-clicking the file.

## Concepts it uses (in order)

1. **HTML:** the page's skeleton, made of tags like `<h1>`, `<input>` and `<ul>`.
   *Analogy:* the walls and rooms of a house. *Where:* lines 19–24.
2. **CSS:** rules that control how things look.
   *Analogy:* paint and furniture. *Where:* lines 8–15. The `.done` rule (line 15) draws the line through finished tasks.
3. **JavaScript:** the code that makes the page react.
   *Analogy:* the electricity that makes the lights work. *Where:* lines 26–84.
4. **DOM (Document Object Model):** the browser's live copy of your page, which JavaScript can change.
   *Analogy:* a model train set you can rearrange while it runs. *Where:* `createElement` and `appendChild`, lines 40–66.
5. **Event:** something the user does that your code waits for, such as a click or a key press.
   *Analogy:* a doorbell that makes you go to the door. *Where:* `addEventListener`, lines 45, 60, 78 and 79.
6. **Array of objects:** a list where each item holds details, here `{ text, done }`.
   *Analogy:* a stack of index cards, each with a task and a done/not-done box. *Where:* `tasks`, line 28. `push` adds a card (line 73) and `splice` removes one (line 61).
7. **localStorage and JSON:** localStorage is a small notebook the browser keeps for your site. It only stores text, so JSON turns your list into text and back.
   *Analogy:* writing your list on a note and sticking it in a drawer. *Where:* lines 28–31.
8. **Render function:** `render()` (line 36) wipes the list and redraws it from the data every time something changes. The data is the truth, and the screen is just a picture of it.
   *Analogy:* redrawing a whiteboard from your notes after every change.

## Expert check

- **Done well:**
  - The input has an `aria-label` (line 21).
  - Each checkbox sits inside a `<label>` (line 51).
  - Each Delete button names its task (line 59).
  - Everything works with the keyboard.
  - `textContent` is used instead of `innerHTML` for the task text (line 53). This stops someone typing HTML code into a task and having it run.
- **Possible gap:** the Add button and its text box aren't in a `<form>`. It works fine now, so this is optional.
- **Watch out:** localStorage is stored per browser, so tasks on your phone won't show on your laptop. Clearing browser data erases them.

## Simplest path

It already is the simplest path: one file, no libraries. A framework like React would add files and installs without adding anything this app needs. The only thing a single file costs you is that it's harder to organize once it grows past a few hundred lines.
